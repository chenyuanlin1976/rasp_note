# GPIO control

To control GPIOs via `/dev/gpiochip*` from an Android application,  
you **cannot** talk to hardware directly from the app layer due to Android's strict sandbox and SELinux policies.  
Instead, you need an **AIDL** (Android Interface Definition Language) service.

The architecture works as follows:

Android App --> AIDL (Binder) --> Native C++ Daemon --> libgpiod --> /dev/gpiochip* --> RK3566 Pins

Here is a step-by-step example of how to implement this on an Android system image  
(such as an RK3566 custom build).

## Step 1: Define the AIDL Interface (IGpioControl.aidl)

Create an AIDL file that defines what methods your hardware service will **expose** to Android applications.

```java
package com.example.gpio;

interface IGpioControl {
    // Set a GPIO line high or low
    boolean setGpioState(int chipNumber, int lineOffset, boolean high);
    
    // Read the current state of a GPIO line
    boolean getGpioState(int chipNumber, int lineOffset);
}
```

## Step 2: Implement the Native C++ Service (libgpiod)

Next, write a native C++ daemon that inherits from the generated binder class  
and uses `libgpiod` to interact with `/dev/gpiochip*`.

```c++
#include <gpiod.h>
#include <android/binder_manager.h>
#include <android/binder_process.h>
#include "com/example/gpio/BnGpioControl.h" // Generated by the build system from your AIDL

class GpioControlService : public com::example::gpio::BnGpioControl {
public:
    ::android::binder::Status setGpioState(int32_t chipNumber, int32_t lineOffset, bool high, bool* _aidl_return) override {
        char chipPath[32];
        snprintf(chipPath, sizeof(chipPath), "/dev/gpiochip%d", chipNumber);

        // 1. Open the gpiochip character device
        struct gpiod_chip *chip = gpiod_chip_open(chipPath);
        if (!chip) {
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        // 2. Get the specific line (pin)
        struct gpiod_line *line = gpiod_chip_get_line(chip, lineOffset);
        if (!line) {
            gpiod_chip_close(chip);
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        // 3. Request the line as an output with initial value
        int ret = gpiod_line_request_output(line, "android_gpio_service", high ? 1 : 0);
        if (ret < 0) {
            gpiod_chip_close(chip);
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        // 4. Set the value and clean up
        gpiod_line_set_value(line, high ? 1 : 0);
        gpiod_line_release(line);
        gpiod_chip_close(chip);

        *_aidl_return = true;
        return ::android::binder::Status::ok();
    }

    ::android::binder::Status getGpioState(int32_t chipNumber, int32_t lineOffset, bool* _aidl_return) override {
        char chipPath[32];
        snprintf(chipPath, sizeof(chipPath), "/dev/gpiochip%d", chipNumber);

        struct gpiod_chip *chip = gpiod_chip_open(chipPath);
        if (!chip) {
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        struct gpiod_line *line = gpiod_chip_get_line(chip, lineOffset);
        if (!line) {
            gpiod_chip_close(chip);
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        // Request line as input to read state
        int ret = gpiod_line_request_input(line, "android_gpio_service");
        if (ret < 0) {
            gpiod_chip_close(chip);
            *_aidl_return = false;
            return ::android::binder::Status::ok();
        }

        int val = gpiod_line_get_value(line);
        gpiod_line_release(line);
        gpiod_chip_close(chip);

        *_aidl_return = (val == 1);
        return ::android::binder::Status::ok();
    }
};
```

## Step 3: Register and Publish the Service (main.cpp)

To make the service accessible via **Binder service manager**:

```c++
#include <android/binder_manager.h>
#include <android/binder_process.h>
#include <binder/ProcessState.h>
#include "GpioControlService.h" // The class defined above

int main() {
    ABinderProcess_setThreadPoolMaxThreadCount(0);
    
    // Instantiate your service
    android::sp<GpioControlService> service = android::make_sp<GpioControlService>();
    
    // Register it with the Android Service Manager under a unique name
    std::string instanceName = std::string(GpioControlService::descriptor) + "/default";
    binder_status_t status = AServiceManager_addService(service->asBinder().get(), instanceName.c_str());
    
    if (status != STATUS_OK) {
        return -1;
    }

    ABinderProcess_joinThreadPool();
    return 0;
}
```

## Step 4: Calling It from an Android App (Java/Kotlin)

Once the native service is running and registered,  
your Android application can look it up and call it seamlessly.

```kotlin
import com.example.gpio.IGpioControl
import android.os.ServiceManager

// Fetch the Binder service
val binder = ServiceManager.getService("com.example.gpio.IGpioControl/default")
val gpioService = IGpioControl.Stub.asInterface(binder)

// Turn on GPIO 4, line 29 (e.g., RK3566 GPIO4_D5)
val success = gpioService?.setGpioState(4, 29, true)
```

## Important RK3566/ Android Integration Notes:

+ **SELinux Permissions**: Because your native service talks directly to `/dev/gpiochip*`,  
  you must update your device's sepolicy files  
  to allow your service's domain (e.g., `gpiod.te`) to read/write `gpio_device_t` (`/dev/gpiochip*`).  
  Otherwise, SELinux will block the operation.
+ `libgpiod` in Android Blueprint (`Android.bp`):  
  Ensure your native service links against `libgpiod` in its `Android.bp` build configuration  
  (shared_libs: ["libgpiod"]).

## `Android.bp` example

To build the native C++ AIDL service that interfaces with `/dev/gpiochip*` using `libgpiod` in your AOSP tree for the RK3566,  
you need an `Android.bp` build file.

Here is a complete, production-ready `Android.bp` example that defines the AIDL interface library,  
the native service executable, and links everything correctly.

```ini
// 1. Define the AIDL interface library so both the service and apps can compile against it
aidl_interface {
    name: "com.example.gpio",
    unstable: true,
    srcs: [
        "com/example/gpio/IGpioControl.aidl",
    ],
    backend: {
        java: {
            enabled: true,
        },
        cpp: {
            enabled: true,
        },
        ndk: {
            enabled: true, // Useful if you prefer using the NDK backend for apps/native code
        },
    },
}

// 2. Build the native C++ Daemon executable that runs in the background
cc_binary {
    name: "gpiod_service",
    init_rc: ["gpiod_service.rc"], // Registers it as a init-managed system daemon
    
    srcs: [
        "GpioControlService.cpp",
        "main.cpp",
    ],

    shared_libs: [
        "libbase",
        "libbinder",
        "libbinder_ndk",
        "libgpiod", // Crucial: Links against libgpiod for /dev/gpiochip* access
        "com.example.gpio-ndk", // Links the C++ bindings generated from our aidl_interface above
    ],

    cflags: [
        "-Wall",
        "-Werror",
    ],

    // Ensure it runs with appropriate system privileges
    vendor: true, // Or system: true depending on whether you place this in vendor/ or system/
}
```

## Accompanying Init Script (gpiod_service.rc)

To make sure Android starts your native daemon automatically during boot,  
create a corresponding `gpiod_service.rc` file in the same directory:

```ini
service gpiod_service /vendor/bin/gpiod_service
    class main
    user root
    group root
    seclabel u:r:gpiod_service:s0
```

## Key Takeaways for your RK3566 AOSP Tree

+ `libgpiod` Dependency: Make sure your device source tree includes `libgpiod`  
  (it is standard in modern AOSP kernels, but verify it's added to your device's PRODUCT_PACKAGES if necessary).
+ AIDL Target Naming: Notice how `com.example.gpio` automatically generates a C++ library target named `com.example.gpio-ndk`  
  (or `com.example.gpio-cpp` depending on the backend you choose) which you include inside `shared_libs`.
